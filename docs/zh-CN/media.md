# 媒体

> 本文译自 [media.md](../media.md)，对应提交 `a1b7eb4`。译文与英文版不一致时，以英文版为准。本译文尚未经过母语者审校，欢迎提交修正。

`tele` 在聊天中直接显示什么、自己播放什么、交给外部程序处理什么。相关设置都位于 `photos:` 下，见 [configuration.md](configuration.md#photos)。

<a id="photos"></a>
## 图片

在 kitty、Ghostty 和 iTerm2 3.7.0 及以上版本中，图片通过 Kitty 图形协议以高画质直接显示在聊天中，其他终端则以 ANSI 字符块画回退显示。tmux 和 screen 不转发该协议，因此在它们中间图片显示为字符块画。

Foot 等支持 DEC sixel、但不支持 Kitty 图片放置的终端可以使用第三种模式：`photos.mode: sixel`（`TERM=foot` 时自动选择）。聊天中的预览（包括并排的相册图片）和图片查看器以终端像素分辨率绘制，下方保留字符块画作为回退。Sixel 属于其覆盖的终端单元格，因此文本更新后会重绘图片。编码结果会被缓存，未变化的帧不会重绘；滚动、面板覆盖或窗口大小变化导致坐标改变后，过时的结果会被丢弃。移动或移除图片时会使终端画面失效一次，以清除文本渲染器无法跟踪的像素。相册标记所在行的图片会被裁剪，为标记保留文本单元格。

窗口大小变化时，即使单元格坐标看起来没有改变，也会使已绘制的图片放置失效。短暂等待会合并连续的大小变化，再清除并重绘；未变化的像素编码仍保留在缓存中。收到单元格大小回复后，也会更新字符块画的布局和消息高度，避免字体变化后预览被拉伸或滚动尺寸过时。调色板采用确定性的构建顺序，字体变化需要重新编码时仍保留颜色。图片查看器也会根据窗口重新计算尺寸，并丢弃在调整大小或关闭前排队的写入，避免过大的图片使终端滚动。

自动检测也识别 mlterm 和 WezTerm。`photos.mode: blocks` 强制使用通用回退；`photos.mode: sixel` 显式选择支持 sixel 的终端。动态 GIF、视频播放和头像继续使用现有的 Kitty 专用路径。

按 `o` 在应用内的查看器中打开原画质图片，边框上显示发送者和时间；按 `O` 在外部查看器中打开。

<a id="terminal-text-alignment"></a>
## 终端文本对齐

宽度库将某些连接符号计为一个单元格，但部分终端会将它们绘制成两个单元格，使同一行后面的内容越过面板边框和图片。最终显示的画面会将这些符号替换为 `?`，以保持测量宽度；存储的名称、消息内容和复制的文本保持不变。符合规范的双单元格符号、键帽和普通文本保留原有字形。

对于包含 virama 的窄辅音组合，在截断和换行前会使用非连写的显示形式。Foot 为每个辅音分配一个单元格，而宽度库可能将整个组合计为一个单元格。插入零宽非连接符可保留字母并使两侧的宽度一致，因此组合连字的外观可能发生变化。存储的文本、实体偏移和超链接目标保持不变。其他终端宽度规则的差异仍可能需要上游修正。

<a id="voice-messages"></a>
## 语音消息

显示带时长的振幅波形，按 `p` 在应用内播放，并有移动的播放位置。

所有平台上的播放都不依赖 cgo：Opus/Ogg 用纯 Go 解码，声音在 macOS 和 Windows 上通过 `oto` 输出，在 Linux 上通过 PulseAudio/PipeWire 协议输出。在 Linux 上需要有正在运行的 PulseAudio 或 PipeWire 服务器，桌面环境默认就是如此。

<a id="video-and-round-video-кружки"></a>
## 视频和圆形视频

在聊天中显示缩略图预览，叠加 `▶` 和时长；圆形视频显示为圆形。按 `o` 用系统播放器播放。

<a id="gifs"></a>
## GIF

在聊天中显示带 `GIF` 标记的静态缩略图。在 Kitty 图形模式下，选中的 GIF 会在原位静音循环播放。这需要 `ffmpeg`，见下文。

<a id="audio-music"></a>
## 音频（音乐）

显示表演者、标题和时长。其他媒体类型显示为带标签的占位符。

<a id="sending-media"></a>
## 发送媒体

用 `u` 附加磁盘上已有的文件（图片、视频、语音、音乐、文档），发送前确认以哪种类型发送。再按一次 `u` 可以添加更多文件：它们会作为一个相册发送，图片和文档会自动分成不同的相册。

<a id="recording-is-out-of-scope"></a>
## 不支持录制

`tele` 可以*发送*预先录好的音频或视频文件，但不能在应用内**录制**语音消息或圆形视频，也不支持实时语音或视频通话。作为不依赖 cgo 的终端客户端，它没有采集麦克风或摄像头的能力。这是架构上的边界，而不是路线图上缺少的功能。

<a id="optional-dependency-ffmpeg"></a>
## 可选依赖：`ffmpeg`

在 `PATH` 中安装 `ffmpeg`（连同 `ffprobe`），即可在聊天中播放 GIF（需要解码帧），并在发送视频时附带时长、尺寸和缩略图。它完全是可选的：没有它，GIF 保持静态，视频照样可以发送，因为 Telegram 会在服务器端生成预览。
