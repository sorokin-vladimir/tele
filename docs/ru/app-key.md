# Ключ приложения

> Перевод [app-key.md](../app-key.md) на коммит `a8ea9ea`. Если перевод расходится с английской версией, верна английская.

`tele` обращается к Telegram с ключом приложения: это пара `api_id` и `api_hash`, которая указывает на приложение, а не на вас.
Делать с ним ничего не нужно: ключ есть в каждой сборке, и вход работает как есть.

<a id="when-telegram-refuses-the-key"></a>
## Когда Telegram отказывает ключу

Сборки из опубликованных исходников (homebrew-core, Nix flake, порт для BSD, ваш собственный `go build`) используют один ключ на всех, кто собирает `tele` таким способом.
Telegram может отказать ключу, которым, по его мнению, пользуются слишком многие.
Тогда `tele` пишет `app key blocked by Telegram`, а не утверждает, что вы вышли из аккаунта.

Обойти это можно двумя способами.
Выберите тот, что проще.

<a id="register-a-key-of-your-own"></a>
### Зарегистрировать свой ключ

Получите ключ на [my.telegram.org](https://my.telegram.org) и пропишите его в `~/.config/tele/config.yml`.
Ваш ключ всегда главнее встроенного:

```yaml
telegram:
  api_id: 123456
  api_hash: "your api hash"
```

Задайте оба значения или ни одного.
Если в конфиге указано одно без другого, `tele` не запустится: половина ключа ничего не обозначает, а если дополнить её половиной встроенного, получится ключ, который никто не выдавал.

В окне настроек видно, какой ключ действует.
Если в конфиге его нет, в строках API ID и API hash вместо числа написано `built-in (official build)` или `built-in (published)`.

Как вшить свой ключ в бинарник, чтобы не читать его из конфига, описано в [development.md](../development.md#building-with-your-own-app-key) (на английском).

<a id="install-an-official-build"></a>
### Установить официальную сборку

У официальных сборок собственный ключ.
Tap для Homebrew, установочный скрипт, apt, dnf, apk, Scoop и winget ставят бинарники, собранные релизным конвейером `tele`.

<a id="which-formula-is-which"></a>
## Какая формула какая

Homebrew может ставить `tele` из двух мест, и разница между ними как раз в ключе.
`brew install tele` из homebrew-core Homebrew собирает из исходников, поэтому в нём общий ключ сборок из исходников.
`brew install sorokin-vladimir/tap/tele` ставит бинарник из релизного конвейера с собственным ключом.

Если tap уже подключён, простой `brew install tele` выберет формулу из tap и сообщит об этом только строкой `Warning: tele shadows homebrew/core/tele`, которую легко пропустить.
Поэтому в README обе формулы записаны полностью.
