<a id="flags-every-command-takes"></a>
## Флаги, которые принимает любая команда

| Флаг                    | Что делает                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `-c`, `--config <path>` | Какой файл конфигурации читать; по умолчанию `~/.config/tele/config.yml`, и на Windows тоже. От него зависит каталог состояния, а значит и то, о каком аккаунте речь |
| `-e`, `--debug`         | Писать лог на уровне debug                                                           |
| `--trace`               | Писать в лог ещё и то, что указывает на чаты и людей: id собеседников, длины сообщений. Никогда не включайте на общей или синхронизируемой файловой системе |
| `-h`, `--help`          | Рассказать, что делает команда и какие флаги принимает                               |

Если файла конфигурации ещё нет, сначала он записывается со значениями по умолчанию.
Лог пишется в `tele.log` в `$XDG_STATE_HOME/tele` или в `~/.local/state/tele`, если переменная не задана, для какого бы аккаунта он ни был.

<a id="tele"></a>
## `tele`

```console
tele [-c PATH]
```

Открывает окно с аккаунтом.
Если аккаунт не держит никакой другой `tele`, его держит этот, пока окно открыто.
Если держит (окно, `tele daemon` или сервис), это окно подключается к нему и использует его соединение.
Если закрыть окно, которое держит аккаунт, пока к нему подключены другие окна, оно сначала спросит, а потом закроет и их.

Когда `tele`, который держит аккаунт, впервые входит в аккаунт на машине, где можно установить сервис, он один раз спрашивает, установить ли его.
См. [Работа без окна](configuration.md#running-without-a-window).

<a id="tele-chats"></a>
## `tele chats`

```console
tele chats [--unread] [--archived | --folder ID] [--limit N] [--json]
```

Перечисляет чаты в том порядке, в каком их показывает список чатов, по строке на чат: id чата, его @username, название и значки (непрочитанные, упоминания, реакции, отметка «непрочитано», выключенные уведомления, а у форума ещё и сколько его тем с непрочитанными).
У чата без юзернейма эта колонка пустая, а если юзернейма нет ни у одного чата в списке, колонки нет совсем.
Юзернейм никогда не обрезается, чтобы его можно было вставить в команду как есть.
Значки начинаются с одной колонки, после самого длинного названия; название шире `cli.name_width` колонок (по умолчанию 20) обрезается.
Без флагов это основной список, без архивных чатов.

| Флаг            | Что делает                                                                      |
| --------------- | ------------------------------------------------------------------------------- |
| `--unread`      | Только чаты, где есть непрочитанное, в том числе отмеченные как непрочитанные   |
| `--archived`    | Архивные чаты вместо основного списка                                           |
| `--folder <id>` | Чаты одной из ваших папок, как их показывает список чатов. Если такой папки нет, команда завершается с кодом 5 и перечисляет те, что есть |
| `--limit <n>`   | Не больше стольких, первые из того, что оставили остальные флаги. Без флага выводятся все |
| `--json`        | По объекту JSON на чат, описано в [cli.md](cli.md#tele-chats---json)            |

<a id="tele-topics"></a>
## `tele topics`

```console
tele topics CHAT [--limit N] [--json]
```

Перечисляет темы форума в том порядке, в каком их показывает список тем, по строке на тему: id темы, её название и значки, а название обрезается по `cli.name_width`, как в `tele chats`.
Если чат не форум, команда завершается с кодом 5.
Этот id принимает `tele show --topic`.

| Флаг          | Что делает                                                            |
| ------------- | --------------------------------------------------------------------- |
| `--limit <n>` | Не больше стольких, первые из списка. Без флага выводятся все         |
| `--json`      | По объекту JSON на тему, описано в [cli.md](cli.md#tele-topics---json) |

<a id="tele-show"></a>
## `tele show`

```console
tele show CHAT [--topic ID] [--limit N] [--before ID] [--mark-read] [--json]
```

Печатает последние сообщения чата, от старых к новым: по строке на сообщение со временем, отправителем и текстом, строку с датой там, где меняется день, и под ответом строку с тем, на что он отвечает.
Текст всех сообщений начинается с одной колонки, после самого длинного имени отправителя; имя шире `cli.name_width` колонок (по умолчанию 20) обрезается.
Медиа только называются и никогда не скачиваются: `[photo]`, `[voice 0:12]`, `[file report.pdf]`.
Чего нет в локальной истории, загружается из Telegram так же, как при прокрутке вверх в окне.

Без просьбы `show` ничего не меняет: с `--mark-read` он отмечает чат прочитанным до последнего напечатанного сообщения, и не дальше.

Сообщения форума лежат в его темах: укажите тему через `--topic`, иначе `show` завершится с кодом 5 и подскажет `tele topics`.

| Флаг            | Что делает                                                                      |
| --------------- | ------------------------------------------------------------------------------- |
| `--topic <id>`  | Какую тему форума показать                                                      |
| `--limit <n>`   | Сколько сообщений: по умолчанию 20, не больше 200                               |
| `--before <id>` | Сообщения старше этого, чтобы листать историю назад                             |
| `--mark-read`   | Отметить чат (или тему) прочитанным до последнего напечатанного сообщения       |
| `--json`        | По объекту JSON на сообщение, описано в [cli.md](cli.md#tele-show---json)       |

<a id="tele-send"></a>
## `tele send`

```console
tele send CHAT [TEXT...] [--topic ID] [--plain] [--ref KEY] [--timeout D] [--no-wait] [--json]
echo "the build is green" | tele send @team
```

Отправляет сообщение: переданные слова через пробел, а если их нет, то, что пришло на stdin.
Разметка читается так же, как в поле ввода (`**bold**`, `` `code` `` и остальное); `--plain` отправляет текст как есть.
В форум сообщение уходит в тему General, если `--topic` не указывает другую.

Сначала сообщение ставится в очередь, как набранное в окне, поэтому переживает перезапуск `tele`, который держит аккаунт.
Затем `send` ждёт, пока оно уйдёт, и печатает id сообщения, которым оно стало:

- Код 6, если сообщение не уйдёт, с объяснением почему.
  Оно остаётся в чате, чтобы человек повторил или удалил его в окне.
- Код 75, если время вышло, а сообщение ещё в очереди, или если пропал `tele`, к которому обращалась команда.
  Сообщение уйдёт само.

`--ref` даёт отправке имя.
Тот же `tele send` с тем же `--ref` второго сообщения не отправит: он дождётся первого или скажет, что оно ушло.
Этим пользуется скрипт, который повторяет попытку после 75 или после потерянного ответа.
Ref помнится 30 дней после того, как его сообщение ушло.

| Флаг              | Что делает                                                                      |
| ----------------- | ------------------------------------------------------------------------------- |
| `--topic <id>`    | В какую тему форума отправить; без флага в General                              |
| `--plain`         | Отправить текст как есть, не читая в нём разметку                               |
| `--ref <key>`     | Дать отправке имя, чтобы повторный запуск той же команды не отправил её дважды  |
| `--timeout <d>`   | Сколько ждать, пока сообщение уйдёт; по умолчанию `30s`                         |
| `--no-wait`       | Вернуться, как только сообщение встало в очередь, с его ref и состоянием        |
| `--json`          | Ответ одним объектом JSON, описано в [cli.md](cli.md#tele-send---json)          |

<a id="tele-version"></a>
## `tele version`

```console
tele version
```

Печатает версию и больше ничего, чтобы её мог прочитать скрипт: `2.0.0`, `2.0.0-beta.11` или `dev` для сборки из исходников без версии.

`tele --version` делает то же самое.
Флаг оставлен для пакетных менеджеров, чьи тесты его вызывают, и в справке не предлагается.

<a id="tele-theme-check"></a>
## `tele theme check`

```console
tele theme check [NAME]
```

Сообщает, во что развернулся каждый слот (тёмный и светлый), через какую цепочку баз он наследовал и сколько токенов откуда взялось, включая те, что откатились к встроенной теме.
Если тема задаёт свой холст, команда ещё и перечисляет токены, которые на нём будет не прочитать.
С `NAME` проверяется только эта тема: слот (`dark`, `light`) или тема по имени (`nord`, `mine`).
Предупреждения о файлах тем выводятся в конце.

`tele --theme-check[=NAME]` делает то же самое и в справке не предлагается.
См. [themes.md](themes.md#when-something-looks-wrong).

<a id="tele-theme-dump"></a>
## `tele theme dump`

```console
tele theme dump [NAME] > ~/.config/tele/themes/mine.yml
```

Выводит тему как полный файл темы, где задан каждый токен, готовый к правке: без `NAME` это тема тёмного слота, иначе слот (`dark`, `light`) или тема с именем `NAME`.
В stdout идёт только сам файл, так что его можно сразу перенаправить; о любой ошибке сообщается в stderr, а код завершения 1.

`tele --theme-dump[=NAME]` делает то же самое и в справке не предлагается.
См. [themes.md](themes.md).

<a id="tele-daemon"></a>
## `tele daemon`

```console
tele daemon [--service]
```

Держит аккаунт без окна, пока его не остановят (Ctrl+C или сигнал от менеджера сервисов).
Поддерживает соединение, показывает системные уведомления, а окна и команды подключаются к нему так же, как к окну.
Он только держит аккаунт: если аккаунт уже держит другой `tele`, он завершается с кодом 1 и называет версию и id процесса того.

| Флаг        | Что делает                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------- |
| `--service` | Работать как сервис: это то, что запускает менеджер сервисов, руками его не набирают. `tele`, запущенный так, не завершается, если аккаунт держит другой, а ждёт и подхватывает аккаунт, когда тот завершится. Он завершается с кодом 75, когда более новый `tele` попросил его перезапуститься, чтобы менеджер сервисов запустил версию, установленную сейчас |

<a id="tele-daemon-status"></a>
## `tele daemon status`

```console
tele daemon status [--json]
```

Сообщает, как дела у `tele`, который держит аккаунт, в том числе у окна: его версию в сравнении с версией этого, что поддерживает его работу (окно, `tele daemon` или сервис) и с какого момента, сколько окон и других команд к нему подключено, в каком состоянии аккаунт, есть ли связь с Telegram, когда пришло последнее обновление, сколько сообщений ждут отправки, о каком ожидании попросил Telegram и ограничены ли команды настройкой [`cli.account_commands`](cli.md#keeping-commands-out-of-your-chats).
Ещё она предупреждает, если установленный сервис запускает команду, которой больше нет, или другую версию, чем эта.

Завершается с кодом 0, если `tele` ответил, и с кодом 3, если не ответил никто.

| Флаг     | Что делает                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------ |
| `--json` | Напечатать ответ одним объектом JSON, описанным в [cli.md](cli.md#tele-daemon-status---json). Если никто не ответил, ничего не печатается |

<a id="tele-daemon-install"></a>
## `tele daemon install`

```console
tele daemon install [--path COMMAND]
```

Поручает операционной системе поддерживать работу `tele` как сервиса для переданного конфига: это LaunchAgent на macOS, пользовательский юнит systemd на Linux и задача Планировщика заданий на Windows.
Сервис запускается при каждом входе в систему и снова, когда завершается, а также прямо сейчас.
Если в этот момент аккаунт держит какой-то `tele`, сервис ждёт и подхватывает аккаунт, когда тот завершится.

Сервис запускает `tele` так, как его находит `PATH`, чтобы обновление заменяло то, что он запускает.
Если `tele` в `PATH` не тот, что выполняет команду, `install` отказывается и называет оба.
Повторная установка заменяет сервис и запускает его заново.
На один файл конфигурации приходится один сервис.
Где устанавливать нечем, потому что нет менеджера сервисов, команда подсказывает, как запускать `tele daemon` из своей сессии, и завершается с кодом 1.

| Флаг               | Что делает                                                                           |
| ------------------ | ------------------------------------------------------------------------------------ |
| `--path <command>` | Команда, которую запускает сервис, вместо `tele`, найденного через `PATH`. Нужен со Scoop, у которого `tele` в `PATH` является прослойкой (shim) |

См. [Как сервис](configuration.md#as-a-service).

<a id="tele-daemon-uninstall"></a>
## `tele daemon uninstall`

```console
tele daemon uninstall
```

Останавливает сервис для переданного конфига и удаляет его.
Окна, подключённые к сервису, получают сообщение, что он удалён, и перестают его ждать.
Состояние и конфиг остаются как были.
Если сервис не установлен, команда так и говорит и завершается с кодом 0.
