# Командная строка

> Перевод [cli.md](../cli.md) на коммит `a8ea9ea`. Если перевод расходится с английской версией, верна английская.

`tele` без команды открывает окно.
Все команды и их флаги описаны в [commands.md](commands.md).
Эта страница описывает договорённости, которые соблюдают все команды: как они названы, с каким кодом завершаются и как выглядит их JSON.

<a id="a-command-needs-a-tele-to-ask"></a>
## Команде нужен `tele`, которого можно спросить

Команда обращается к `tele`, который держит аккаунт: к открытому окну или к сервису.
Своего `tele` она никогда не запускает.
Если ни один не запущен, она завершается с кодом 3 и подсказывает, как его получить: открыть `tele` или установить сервис через `tele daemon install`.
Поэтому для скриптов нужен сервис: он работает с момента входа в систему, открыто окно или нет.
См. [Работа без окна](configuration.md#running-without-a-window).

Работающая команда не считается человеком, который смотрит в аккаунт: она не мешает показать системное уведомление, а окно при выходе не считает её среди окон, которые закроются вместе с ним.

Команда, которая действует в аккаунте, ждёт, пока он будет готов: пока `tele`, который держит аккаунт, подключается, загружает список чатов или запускает следующий аккаунт после выхода.
Ждёт она не больше 30 секунд.
Если аккаунт ждёт, что в него войдут, команда сразу завершается с кодом 4: вход выполняется в окне.

<a id="naming-a-chat"></a>
## Как указать чат

Команда указывает чат одним из трёх способов, одинаково во всех командах:

| Имя         | Какой чат                                                                      |
| ----------- | ------------------------------------------------------------------------------ |
| `42`        | Чат с этим id, как его печатает `tele chats`                                   |
| `@username` | Пользователь, бот или канал с этим username, в любом регистре. Если его нет среди ваших чатов, он запрашивается у Telegram |
| `me`        | Ваш собственный чат, Избранное                                                 |

Название чата ничего не указывает: названия меняются, и у двух чатов может быть одно и то же.
Всё остальное завершается с кодом 2, а имя, за которым нет чата, с кодом 5.

<a id="keeping-commands-out-of-your-chats"></a>
## Как не пускать команды в переписку

`cli.account_commands` в конфиге `tele`, который держит аккаунт, говорит, что командам можно делать с ним:

| Значение | Что можно командам                                                           |
| -------- | ---------------------------------------------------------------------------- |
| `all`    | Всё, по умолчанию                                                            |
| `read`   | Перечислять и показывать, ничего не меняя: `tele send` и `tele show --mark-read` получают отказ |
| `none`   | Ничего: любая команда, которая действует в аккаунте, получает отказ         |

То, что запрещено, завершается с кодом 7.
Настройка нужна для скрипта или ИИ-агента, которому вы разрешили запускать `tele`: с `read` он сможет читать ваши чаты, но не писать в них, с `none` не получит ничего.
Это настройка `tele`, который держит аккаунт, а не команды, поэтому команда с другим файлом конфигурации подчиняется ей так же, а менять настройки `tele`, к которому обращается, команда не может никогда.
`tele daemon status` показывает, что разрешено.
Окон настройка не касается.

Она закрывает переписку только от собственных команд `tele`, не больше.
Программа, запущенная от вашего пользователя, может сама прочитать каталог состояния, где лежат история и сессия, или обратиться к `tele`, который держит аккаунт, так, как это делает окно.
Не пускать программу туда должны права на файлы или песочница.

<a id="how-commands-are-named"></a>
## Как названы команды

1. Команды верхнего уровня действуют в Telegram; поддерево `daemon` действует на `tele`, который держит аккаунт.
2. Команды называются целыми словами: никаких `tele ls` и `tele d`.
3. Длинные флаги пишутся с двумя дефисами, `--name`.
   Короткая форма есть только у того, что набирают руками: `-c` для `--config`, `-h` для `--help`, `-e` для `--debug`.
4. У флага, действие которого трудно отменить, короткой формы нет.
5. Вывод для программ включается флагом `--json`, в каждой команде, где он есть.
6. Одно и то же значение называется одинаково во всех командах, например `--limit`.
7. Чат во всех командах указывается одинаково.
8. Действие оформляется командой, а флаг только уточняет её.
   Поэтому `tele version` и `tele theme check`, а не `--version` и `--theme-check`.
   Эти два флага и `--theme-dump` по-прежнему работают для пакетных менеджеров, которые их вызывают, но в справке не предлагаются.

<a id="exit-codes"></a>
## Коды завершения

| Код  | Значение                                                                        |
| ---- | ------------------------------------------------------------------------------- |
| 0    | Готово                                                                          |
| 1    | Что-то другое пошло не так; что именно, сказано в stderr                        |
| 2    | Не удалось разобрать командную строку: неизвестный флаг, команда или аргумент   |
| 3    | Нет `tele`, который держит аккаунт и которого можно спросить                    |
| 4    | В аккаунт не выполнен вход                                                      |
| 5    | Нет такого чата, темы или папки                                                 |
| 6    | Сообщение не удалось отправить, и повторная попытка этого не изменит            |
| 7    | `tele`, который держит аккаунт, не разрешает командам это делать: см. `cli.account_commands` |
| 75   | Ожидание прервано, пока сообщение ещё стояло в очереди, или Telegram попросил подождать; позже может получиться |

Скрипт отличает 75, при котором стоит попробовать позже, от 6, при котором не стоит.
Сообщение, получившее 75, стоит в очереди и уйдёт само; тот же `tele send` с тем же `--ref` снова дождётся его и не отправит второй раз.
Сообщение, получившее 6, остаётся в чате, чтобы человек повторил или удалил его в окне.

<a id="json"></a>
## JSON

- Для программ есть единственный формат, `--json`.
  Для YAML: `| yq -P`.
- Команда, которая отвечает одним объектом, печатает один объект.
  Команда, которая отвечает списком, печатает JSON Lines: по объекту на строку, от старых к новым там, где порядок означает время.
- Имена полей в `snake_case`.
  Время в формате RFC 3339.
- Поле, которое неприменимо, не выводится вовсе, а не выводится как ноль или null.
  Скрипт читает отсутствующее поле как «нет», а не как «ноль».
- Всё описанное здесь сохраняется в пределах мажорной версии: поля могут добавляться, но ни одно не будет переименовано или удалено до tele 3.
- Если команда завершилась с ошибкой, stdout остаётся пустым: причину сообщают код завершения и stderr.

<a id="tele-chats---json"></a>
## `tele chats --json`

```json
{"id":42,"title":"Bob","username":"bob","kind":"user","unread":3,"mentions":1,"reactions":0,"unread_mark":false,"muted":false,"archived":false,"forum":false}
{"id":300,"title":"Gophers","kind":"group","unread":1,"mentions":0,"reactions":2,"unread_mark":true,"muted":true,"archived":false,"forum":true}
```

| Поле          | Что это                                                                                |
| ------------- | -------------------------------------------------------------------------------------- |
| `id`          | То, чем чат указывается в любой команде                                                |
| `title`       | Название чата или имя человека                                                         |
| `username`    | Его публичный username без `@`; отсутствует, если username нет                         |
| `kind`        | `user`, `bot`, `group` или `channel`                                                   |
| `unread`      | Сколько сообщений не прочитано; у форума: сколько его тем с непрочитанными             |
| `mentions`    | Сколько непрочитанных сообщений упоминают вас                                          |
| `reactions`   | Сколько реакций на ваши сообщения вы не видели                                         |
| `unread_mark` | Отмечен ли чат как непрочитанный вручную                                               |
| `muted`       | Выключены ли у него уведомления                                                        |
| `archived`    | Лежит ли он в архиве                                                                   |
| `forum`       | Форум ли это, у которого сообщения лежат в темах                                       |

<a id="tele-topics---json"></a>
## `tele topics --json`

```json
{"id":17,"title":"Releases","unread":4,"mentions":1,"reactions":0,"muted":true,"pinned":false,"closed":false}
```

| Поле        | Что это                                                            |
| ----------- | ------------------------------------------------------------------ |
| `id`        | То, что принимает `tele show --topic`                              |
| `title`     | Название темы                                                      |
| `unread`, `mentions`, `reactions` | Как у чата, но в пределах этой темы          |
| `muted`     | Выключены ли уведомления темы, её собственной настройкой или настройкой форума |
| `pinned`    | Закреплена ли она наверху списка                                   |
| `closed`    | Пишут ли в неё только администраторы                               |

<a id="tele-show---json"></a>
## `tele show --json`

```json
{"id":512,"date":"2026-10-25T09:12:00+03:00","sender_id":77,"sender":"Ada Lovelace","out":true,"text":"morning!","reply_to":511}
{"id":513,"date":"2026-10-25T09:13:00+03:00","sender_id":42,"sender":"Bob","out":false,"media":{"kind":"voice","duration":12}}
```

| Поле        | Что это                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------- |
| `id`        | Id сообщения, его принимает `--before`                                                      |
| `date`      | Когда оно отправлено                                                                        |
| `sender_id`, `sender` | Кто его отправил, id и имя; у ваших сообщений ваши. В канале это сам канал        |
| `out`       | Отправили ли его вы                                                                         |
| `text`      | Текст или подпись к медиа; отсутствует, если их нет                                         |
| `reply_to`  | Id сообщения, на которое оно отвечает; отсутствует, если это не ответ                       |
| `media`     | Какие медиа в нём, отсутствует, если их нет: `kind` (`photo`, `video`, `round_video`, `voice`, `audio`, `sticker`, `gif`, `file`, `location` или `other`) и то, что медиа сообщают о себе: `duration` в секундах, `file_name`, `size` в байтах, `title`, `performer`, `emoji`. Где лежит файл, не выводится никогда: ничего не скачивается |

<a id="tele-send---json"></a>
## `tele send --json`

Когда сообщение ушло:

```json
{"chat_id":42,"message_id":512,"date":"2026-10-25T09:30:00+03:00"}
```

| Поле         | Что это                                                                         |
| ------------ | ------------------------------------------------------------------------------- |
| `chat_id`    | Чат, в который оно ушло                                                         |
| `topic_id`   | Тема форума, в которую оно ушло; отсутствует вне форума                         |
| `message_id` | Сообщение, которым оно стало; отсутствует в редком случае, когда Telegram его не назвал |
| `date`       | Когда оно ушло                                                                  |

С `--no-wait`, когда сообщение поставлено в очередь:

```json
{"ref":"nightly-report","state":"queued"}
```

| Поле    | Что это                                                                            |
| ------- | ---------------------------------------------------------------------------------- |
| `ref`   | Имя отправки: переданный `--ref` или придуманный                                   |
| `state` | `queued`, `sending`, `failed` или `sent`, если тот же ref уже уходил раньше         |

Если сообщение не ушло, ничего не печатается: причину сообщают код завершения (6 или 75) и stderr.

<a id="tele-daemon-status---json"></a>
## `tele daemon status --json`

```json
{
  "state_dir": "/home/ada/.local/state/tele",
  "host": {"binary": "2.0.2", "protocol": 6, "pid": 4242, "kept": "service", "config": "/home/ada/.config/tele/config.yml"},
  "since": "2026-10-21T09:00:00Z",
  "windows": 1,
  "commands": 0,
  "account_commands": "all",
  "account": {
    "phase": "ready",
    "user": "ada",
    "link": "up",
    "link_since": "2026-10-21T09:00:04Z",
    "last_update": "2026-10-21T12:41:10Z",
    "outbox": 0,
    "throttle": {"method": "messages.getHistory", "until": "2026-10-21T12:41:42Z"}
  },
  "this": {"binary": "2.0.2", "protocol": 6},
  "service_warning": "The service runs /opt/homebrew/bin/tele, which is not there any more."
}
```

| Поле               | Что это                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| `state_dir`        | Каталог состояния, о котором спрашивали                                                        |
| `host`             | `tele`, который его держит: версия, протокол, id процесса, файл конфигурации и `kept`: `window`, `daemon` или `service` |
| `since`            | Когда этот `tele` запустился                                                                   |
| `windows`          | Сколько окон к нему подключено                                                                 |
| `commands`         | Сколько других команд обращаются к нему прямо сейчас                                           |
| `account_commands` | Что командам можно делать с аккаунтом: `all`, `read` или `none`, как говорит [`cli.account_commands`](#keeping-commands-out-of-your-chats) |
| `account`          | Аккаунт; отсутствует в промежутке между одним аккаунтом и следующим                            |
| `account.phase`    | `connecting`, `logging_in`, `loading` или `ready`                                              |
| `account.user`     | Username пользователя, под которым выполнен вход; отсутствует, пока Telegram его не сообщил, или если username нет |
| `account.ended`    | Чем закончилось соединение; отсутствует, пока оно работает                                     |
| `account.link`     | `up`, `down` или `unknown`; с какого момента, показывает `link_since`                          |
| `account.last_update` | Когда пришло последнее обновление от Telegram                                               |
| `account.outbox`   | Сколько сообщений ждут отправки                                                                |
| `account.throttle` | Ожидание, о котором попросил Telegram и которое что-то задерживает, и до какого момента; отсутствует, если ожидания нет |
| `this`             | `tele`, который спрашивал: его версия и протокол                                               |
| `service_warning`  | Что не так с установленным сервисом; отсутствует, если всё в порядке                           |

`tele`, который говорит на другой версии протокола, только называется: есть `host` и `this`, и ничего сверх того, о чём его спросили.
Если каталог состояния никто не держит, ничего не печатается, а код завершения 3.
