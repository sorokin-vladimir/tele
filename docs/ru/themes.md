# Темы

> Перевод [themes.md](../themes.md) на коммит `a8ea9ea`. Если перевод расходится с английской версией, верна английская.

У каждого цвета, который рисует tele, есть имя: это токен.
**Тема** задаёт значения этих токенов, и вы можете написать свою.

<a id="slots"></a>
## Слоты

tele держит две темы одновременно, по одной на **слот**: тёмный слот используется, когда фон терминала тёмный, а светлый, когда светлый.
tele следует за терминалом и переключается вместе с вашей ОС или терминалом.

Слоты настраиваются в `ui.theme`, который принимает либо имя, либо словарь:

```yaml
ui:
  # Nothing set: the built-in tele-dark and tele-light.

  theme: gruvbox-dark        # this theme in both slots, whatever the background

  theme:
    dark: gruvbox-dark       # dark slot from a file
    light: solarized-light   # light slot from another

  theme:
    dark: gruvbox-dark       # dark slot from a file, light slot stays built-in
```

Если указать одну тему, она займёт оба слота: так говорят «эта тема, всегда».
Отдельного переключателя, чтобы перестать следовать за терминалом, нет: в обоих слотах одна и та же тема.

Встроенные темы называются **`tele-dark`** и **`tele-light`**.
С них начинается любая цепочка: токен, который не задала ни одна тема, берётся из встроенной темы этого слота, поэтому теме никогда не нужно быть полной, и она не ломается, когда в tele появляется новый токен.

> `ui.theme: default` был в каждом конфиге, который tele записывал до появления тем.
> Он обозначал пару, а пар больше нет.
> Его игнорируют с предупреждением; удалите эту строку.

<a id="writing-a-theme"></a>
## Как написать тему

Файлы тем лежат рядом с конфигом, в `~/.config/tele/themes/`, по одной теме на файл, и тема называется по файлу: `themes/mine.yml` содержит тему `mine`.
Читаются и `.yml`, и `.yaml`.
В имени `-` и `_` равнозначны, а регистр не важен, поэтому `my-theme`, `my_theme` и `MyTheme` называют одну и ту же тему.

Быстрее всего начать с того, что у вас уже работает, и отредактировать:

```console
tele theme dump > ~/.config/tele/themes/mine.yml
tele theme dump light > ~/.config/tele/themes/mine-light.yml
```

Или начать с одной из палитр, которые уже поставляются с tele.
Catppuccin Macchiato, Dracula, Gruvbox Dark, Nord, Tokyo Night (Night, Moon и Day) и Seoul256 Light относятся к **поставляемым** темам: они внутри бинарника, поэтому `ui.theme: nord` работает на машине вообще без файлов тем, и ничего никуда копировать не нужно.
Каждая задаёт все токены и задаёт свой холст, и в каждой есть комментарии о палитре, из которой она взята, и о местах, где от неё пришлось отступить.
Файлы лежат в [`themes/`](../../themes/), если хотите прочитать какой-то перед выбором.

Чтобы изменить поставляемую тему, а не просто использовать её, укажите её как базу (см. ниже) или выгрузите и отредактируйте результат: `tele theme dump nord > ~/.config/tele/themes/mine.yml`.

Чтобы поменять несколько цветов, лучше наследовать.
`base:` называет тему, из которой эта тема берёт всё, что не задаёт сама:

```yaml
# ~/.config/tele/themes/mine.yml
base: tele-dark
border_pane_active: "#8ec07c"
accent: bright-blue
```

`base:` может назвать встроенную тему, поставляемую или другой ваш файл, и цепочки прослеживаются до конца.
О цикле сообщается, и слот остаётся со встроенной темой.

<a id="when-two-themes-have-one-name"></a>
### Когда у двух тем одно имя

Ваши файлы главнее поставляемых палитр.
На вашей машине `nord` означает `~/.config/tele/themes/nord.yml`, и он **полностью заменяет** поставляемый `nord`: то, чего он не задаёт, берётся из встроенной темы, а не из палитры, чьё имя он занял.
Если вы хотели подправить поставляемую тему, назовите свой файл иначе и укажите `base: nord`.

Исключение составляют две встроенные темы.
Файл `tele-dark.yml` или `tele-light.yml` игнорируется с предупреждением, потому что `base: tele-dark` должен означать одну и ту же палитру на любой машине, иначе тема, скопированная у кого-то другого, развернулась бы у вас в другие цвета, чем у него.

<a id="colors"></a>
## Цвета

Токен хранит цвет и ничего больше.
Насыщенность шрифта, наклон, отступы и символы рамок относятся к компоненту, который рисует элемент, а не к теме, поэтому `bold` или `italic` здесь задать нельзя.
Такова тема сегодня, и это не обещание того, какой она будет всегда.

Токен принимает любую из форм:

| Форма          | Пример        | Примечание                               |
| -------------- | ------------- | ---------------------------------------- |
| Длинный hex    | `"#8ec07c"`   | Возьмите в кавычки, иначе YAML прочитает `#` как комментарий |
| Короткий hex   | `"#8ec"`      | Разворачивается в `#88eecc`              |
| Индекс палитры | `240`         | 0–255                                    |
| Имя ANSI       | `bright-blue` | Шестнадцать имён ниже                    |
| `none`         | `none`        | Цвета нет вообще                         |

Шестнадцать имён: `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white` и форма `bright-` каждого из них.

Индекс или имя в диапазоне 0–15 **не** сокращает hex-значение: они берутся из палитры, настроенной в вашем терминале.
Если написать тему ими, tele будет следовать за терминалом, а не перекрывать его.

`none` значит, что атрибут не задан.
Как цвет текста он даёт собственный цвет текста терминала; как фон он ничего не закрашивает, и это единственный способ сохранить прозрачность терминала: на `background` именно он оставляет весь экран терминальным:

```yaml
surface_overlay: none
```

`none` не принимается для `highlight_accent`, `highlight_error`, `highlight_base_chat` и `highlight_base_bubble`.
Эти четыре токена не рисуются напрямую, а используются для плавного перехода, и «нет цвета» молча означало бы чёрный.

<a id="the-two-list-tokens"></a>
## Два токена-списка

`sender_palette` выбирает цвет для каждого отправителя по id и принимает любое количество значений:

```yaml
sender_palette: ["#ff5f5f", "#5fd75f", bright-blue, none]
```

`logo_gradient` задаёт шкалу, по которой переливается логотип на заставке.
Ей нужно не меньше двух точек по возрастанию, начиная с 0 и заканчивая 1:

```yaml
logo_gradient:
  - { pos: 0.0, color: "#3c5aa0" }
  - { pos: 0.5, color: "#82aae6" }
  - { pos: 1.0, color: "#d7eeff" }
```

Если задать любой из них, он **заменяет** список, унаследованный от базы, а не сливается с ним.
Чтобы поменять цвет одного отправителя, перечислите все.

<a id="when-something-looks-wrong"></a>
## Когда что-то выглядит не так

```console
tele theme check
```

печатает, во что развернулся каждый слот, через какую цепочку он наследовал и сколько токенов откуда взялось, включая те, что откатились к встроенной теме, потому что их не задал никто в вашей цепочке.
`tele theme check mine` проверяет одну тему по имени.

Каждая тема в цепочке печатается с указанием, откуда она взялась, а это как раз то, чего экран показать не может:

```
dark slot: nord
  chain: nord (file) <- tele-dark (built-in)
  note: nord is also a bundled theme; the file is used
```

`file` означает одну из ваших тем, `bundled` палитру, которая поставляется внутри бинарника, а `built-in` тему `tele-dark` или `tele-light`.

Всё, что tele не смог использовать (отсутствующая тема, нечитаемый файл, цвет, который не удалось разобрать, неизвестный ключ), даёт предупреждение, а не отказ запускаться.
Предупреждения появляются тостами при открытии tele и в `~/.local/state/tele/tele.log`.
Неизвестный ключ игнорируется, а остальной файл используется, поэтому тема, написанная для более поздней версии tele, работает и здесь.

<a id="what-will-not-be-readable"></a>
### Что будет не прочитать

Если ваша тема задаёт `background`, `tele theme check` ещё и измеряет всё, что рисуется прямо на этом холсте (каждый токен текста и каждый элемент `sender_palette`), и перечисляет то, что не дотягивает до контраста 3.0:1 с ним:

```
  canvas #ffffff: 15 tokens and 7 sender_palette entries below 3.0:1
    markup_link           1.09:1   from mine
    sender_palette[4]     1.22:1   from tele-dark
    name_editing          1.39:1   from tele-dark
    …
```

Сначала самые плохие, потому что 1.1:1 не видно вовсе, а 2.8:1 просто приглушено.
Читать нужно последний столбец: `from mine` значит, что этот цвет написали вы и можете его поменять, а `from tele-dark`, что вы его унаследовали и должны задать токен в своём файле.
В примере выше обычная случайность: светлый холст на цепочке, которая начинается с `tele-dark`, а та даёт палитру текста, подобранную для чёрного фона.

Токен, оставленный в `none`, тоже попадает в список, но без соотношения: измерить нечего, ведь `none` означает собственный цвет текста терминала, который никак не связан с вашим холстом.

При запуске и при перечитывании вы получаете по одному тосту на тему, а не на токен, с тем, сколько их и где подробности:

```
theme mine: 15 tokens and 7 sender_palette entries are unreadable on its canvas; run tele theme check
```

Ничто из этого ничего не запрещает.
Тема загружается и рисуется ровно так, как вы её написали: порог служит ориентиром, а не правилом, и он установлен на 3.0:1, а не на 4.5:1, принятые для основного текста, как раз для того, чтобы токены, задуманные приглушёнными, могли такими и оставаться.
Если вы не согласны с находкой, не обращайте на неё внимания.

Так сделано намеренно, а не по недоделке.
Контраст считается по относительной яркости и не видит оттенка, поэтому неверно оценивает насыщенный цвет рядом с нейтральным: собственный акцент tele-dark даёт 1.29:1 с текстом, который он выделяет, и при этом прекрасно читается.
Если навязывать порог через мерку, которая заведомо ошибается определённым образом, будут отклоняться нормальные темы без всякой возможности возразить.
Предупреждение можно потом ужесточить, если появятся доказательства; запрет нельзя ослабить, не сломав уже написанные людьми файлы.

Две вещи эта проверка не делает.
Тема, которая не задаёт `background`, не проверяется вовсе: тогда холст принадлежит терминалу, и tele его не видит; встроенные темы вместо этого покрыты собственными тестами.
И токены, которые рисуются на поверхности, закрашиваемой самим приложением (`text_on_toast`, `accent_status_bar`), здесь не измеряются: их нужно оценивать относительно этой поверхности, а не холста.

<a id="editing-a-theme-while-tele-runs"></a>
## Правка темы на ходу

Действие `reload_config` заново читает файлы тем и файл конфигурации и применяет и то и другое без перезапуска.
По умолчанию **клавиша на него не назначена**, потому что оно полезно, только пока вы что-то правите в другом окне, чаще всего тему, где перезапуск стоил бы переподключения ради каждого пробного цвета.
Назначьте его, когда понадобится:

```yaml
keybindings:
  global:
    reload_config: ctrl+t
```

`reload_themes` было именем этого действия, когда оно читало только файлы тем.
Оно по-прежнему работает и делает то же самое, так что конфиг, где оно уже назначено, менять не нужно.

После перечитывания сообщается, что найдено: развёрнутая тема в каждом слоте или первая проблема и сколько ещё в логе.
Обо всём неправильном в файле конфигурации (значение, которое tele не примет, тема, которой нет) сообщается так же.

<a id="tokens"></a>
## Токены

`tele theme dump` выводит текущее значение каждого токена.
Что раскрашивает каждый:

<a id="surfaces---filled-areas-drawn-behind-content"></a>
### Поверхности: закрашенные области под содержимым

| Токен                  | Где                                                    |
| ---------------------- | ------------------------------------------------------ |
| `surface_overlay`      | всплывающие меню, выбор реакции, подсказка упоминаний  |
| `surface_help`         | панель окна справки                                    |
| `surface_toast`        | панель тоста                                           |
| `surface_status_bar`   | строка состояния                                       |
| `surface_selected`     | заливка выбранной строки, рамка подсказки упоминаний, строка поиска |
| `surface_self_mention` | @упоминание вас                                        |
| `surface_code`         | код в строке и блоки кода                              |

<a id="text"></a>
### Текст

| Токен                    | Где                                                                               |
| ------------------------ | --------------------------------------------------------------------------------- |
| `text`                   | основной текст: текст сообщений, названия чатов, подписи папок, строки поиска, счётчик непрочитанных |
| `text_dim`               | время, цитаты, разделители                                                        |
| `text_muted`             | чаты с выключенными уведомлениями                                                 |
| `text_faint`             | «no results», «empty», описания подсказок в окнах                                 |
| `text_subtle`            | строка о не поместившихся тостах                                                  |
| `text_on_surface`        | текст окна справки                                                                |
| `text_status_bar`        | текст строки состояния                                                            |
| `text_on_selected`       | текст поверх `surface_selected`                                                   |
| `text_on_selected_muted` | второстепенный текст поверх `surface_selected`                                    |
| `text_on_toast`          | текст тоста                                                                       |
| `text_mode_label`        | метка NORMAL/INSERT                                                               |
| `text_code`              | код в строке и блоки кода                                                         |

`text` занимает самую большую цветную область на экране, и именно она решает, узнаётся ли тема.
Встроенные темы оставляют его `none`, то есть собственный цвет текста терминала, как было до появления этого токена, поэтому тема должна задать его намеренно.

<a id="the-canvas"></a>
### Холст

`background` задаёт цветное поле позади всего, там, где его не закрывает ни одна поверхность.
Обе встроенные темы оставляют его `none`, то есть фон терминала, как tele выглядел всегда, поэтому ничего не меняется, пока тема его не задаст.

| Токен        | Где                                                  |
| ------------ | ---------------------------------------------------- |
| `background` | весь экран, позади каждой панели, строки и пузыря    |

**`background` требует `text`.**
Тема, которая задаёт одно без другого, отклоняется с предупреждением и рисуется так, будто не задала ни того, ни другого.
Дело не в аккуратности: если закрасить экран, а текст оставить терминалу, под неизвестным цветом текста окажется известный фон.
Такое сочетание однажды уже было выпущено в масштабе панелей: всплывающие меню выходили синими на сером в светлом терминале, и выделенную акцентом клавишу было не отличить от подписи вокруг.
В масштабе холста это закрывает всё.

Требование проверяется на теме, которая получается из всей цепочки `base:`, а не на файле перед вами, поэтому разносить их по разным слоям можно:

```yaml
# palette.yml
text: "#cdd6f4"

# mine.yml
base: palette
background: "#1e1e2e" # accepted: the chain supplies text
```

Требование действует только в одну сторону.
`text` без `background` допустим, и именно так поступили бы встроенные темы, если бы задавали основной текст.

**Если его задать, прозрачность терминала пропадёт.**
Прозрачный терминал показывает обои сквозь ячейки, которые tele не закрашивает, а холст закрашивает их все.
Частичного варианта нет: чтобы сохранить фон, оставьте `background` незаданным.

Перед тем как его задать, полезно знать ещё две вещи:

- Все остальные токены, которые рисуются _на_ холсте (`text_dim`, `status_online`, `tick_read`, `name_incoming`, вся `sender_palette`), по-прежнему берутся из того, с чего начинается ваша цепочка.
  Тема, которая рисует светлый холст, но начинается с `tele-dark`, наследует палитру текста, подобранную для чёрного фона, и несколько этих токенов будет почти не видно.
  После того как зададите холст, запустите `tele theme check`: когда тема называет свой холст, tele может измерить токены относительно него и сказать, какие именно.
  См. [Что будет не прочитать](#what-will-not-be-readable).
- Изображения продолжают работать.
  Изображение Kitty рисуется поверх своих ячеек, а холст виден там, где изображение прозрачно, и это даже улучшение: без холста в прозрачных пикселях был виден терминал, и в остальном закрашенном экране оставались дыры по форме изображения.

<a id="accents"></a>
### Акценты

Акцентов три, потому что акцент рисуется на трёх разных фонах, и в светлой теме они не совпадают: фон терминала светлый, а строка состояния и (в большинстве тем) всплывающие панели не светлые.

| Токен                | Где                                                                                            |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| `accent`             | на фоне терминала: подсказки фото, видео и поиска, у которых нет панели позади                 |
| `accent_on_surface`  | на панели, которую закрашивает приложение: окно справки, всплывающие меню, номера в выборе, действие в тосте |
| `accent_status_bar`  | на строке состояния в режиме NORMAL                                                            |
| `accent_insert`      | на строке состояния в режиме INSERT                                                            |
| `accent_mode_normal` | заливка метки NORMAL                                                                           |
| `accent_mode_insert` | заливка метки INSERT                                                                           |

Если ваша тема рисует тёмную строку состояния под светлым терминалом (как `tele-light`), оставьте `accent_status_bar` и `accent_insert` светлыми.
Это единственные два акцента, чей фон не следует за терминалом.

<a id="status-and-message-state"></a>
### Статусы и состояние сообщений

| Токен                                                  | Где                                    |
| ------------------------------------------------------ | -------------------------------------- |
| `status_error`, `status_warning`, `status_info`        | тосты и сообщения о состоянии          |
| `status_online`                                        | точка «в сети»                         |
| `tick_sent`, `tick_outbox`, `tick_read`, `tick_failed` | галочки доставки                       |
| `name_incoming`                                        | имя отправителя входящего              |
| `name_editing`                                         | имя во время правки                    |
| `indicator`                                            | полоска выделения рядом с пузырём      |
| `unread_separator`                                     | разделитель непрочитанных              |
| `waveform_played`                                      | проигранная часть волны голосового     |
| `reaction_chosen`                                      | реакция, которую поставили вы          |

<a id="highlights"></a>
### Подсветка

| Токен                   | Где                                      |
| ----------------------- | ---------------------------------------- |
| `highlight_accent`      | подсветка при переходе, угасающая к своей базе |
| `highlight_error`       | отменённое действие                      |
| `highlight_base_chat`   | тон, к которому угасает подсветка строки чата |
